## Комментарий подхода

**Пагинация (limit/offset)**:

* **Простота для мобильного клиента**: offset‑пагинация легко реализуется в UI (скролл «показать ещё», кнопки «дальше/назад»), не требует хранения токенов состояния.
* **Совместимость с фильтрацией и сортировкой**: при комбинации `status=upcoming`, `limit=20`, `offset=40` сервер возвращает предсказуемый срез данных; общее поле `total` позволяет клиенту рассчитать количество страниц.
* **Контроль нагрузки**: жёсткие лимиты (`1 ≤ limit ≤ 100`) защищают бэкенд от тяжёлых запросов и упрощают планирование SLA.

**Версионирование в URL (`/api/v1/`)**:

* **Явная граница контракта**: версия в пути делает несовместимости явными — клиент всегда знает, с какой версией API он работает.
* **Упрощение эксплуатации**: балансировщики и шлюзы легко маршрутизируют по префиксу, отдельные версии можно деплоить и отключать независимо.
* **Соответствие практике «Здоровье+»**: учитывая наличие Legacy‑систем и поэтапную миграцию (MVP → финальное решение), такой подход позволяет параллельно поддерживать старые клиенты (веб‑портал) и новые (мобильное приложение) без конфликтов.
